# quiz-game — 터미널 퀴즈 게임 (주제: 일본 애니메이션 제목 맞추기)

유명 일본 애니메이션의 제목을 맞히는 콘솔 퀴즈 게임. 메뉴에서 번호를 골라 퀴즈를 풀고, 추가하고, 목록과 최고 점수를 확인한다. 프로그램을 종료한 뒤 다시 실행해도 추가한 퀴즈와 최고 점수가 그대로 유지된다.

## 실행 방법

```
python main.py
```

- Python 3.10 이상, 외부 라이브러리 없이 표준 라이브러리(`json`, `os`)만 사용한다.

## 기능 목록

| 메뉴 | 기능 | 설명 |
| --- | --- | --- |
| 1 | 퀴즈 풀기 | 등록된 문제를 순서대로 출제하고 정답/오답을 판정한 뒤 최종 점수(100점 만점)를 보여준다. 퀴즈가 없으면 안내한다. |
| 2 | 퀴즈 추가 | 문제·선택지 4개·정답 번호(1~4)를 입력받아 등록하고 `state.json`에 저장한다. |
| 3 | 퀴즈 목록 | 등록된 문제 목록을 번호와 함께 보여준다. 없으면 안내한다. |
| 4 | 점수 확인 | 지금까지의 최고 점수를 보여준다. 아직 풀지 않았으면 안내한다. |
| 5 | 종료 | 현재 상태를 저장하고 종료한다. |

## 파일 구조

```
quiz-game/
├── main.py       # 프로그램 전체 (Quiz, QuizGame 클래스 + 입력/메뉴 함수)
├── state.json    # 퀴즈·최고 점수 저장 파일 (실행 중 자동 생성, .gitignore 처리)
├── .gitignore
└── README.md
```

## 데이터 파일 설명 (state.json)

- **위치**: 프로젝트 루트 / **인코딩**: UTF-8
- **역할**: 추가한 퀴즈와 최고 점수를 저장해, 프로그램을 종료한 뒤 다시 실행해도 상태가 유지되게 한다("데이터 영속성").
- **구조**:

```json
{
  "quizzes": [
    {"question": "문제 내용", "choices": ["1번", "2번", "3번", "4번"], "answer": 2}
  ],
  "best_score": 80
}
```

- `quizzes`: 퀴즈 목록(list). 각 퀴즈는 `question`(문제, str), `choices`(선택지 4개, list), `answer`(정답 번호 1~4, int)로 이뤄진 dict.
- `best_score`: 지금까지의 최고 점수(int, 백분율).
- **읽기/쓰기 흐름**: 프로그램 시작 시 `QuizGame.load()`가 한 번 읽고(없으면 기본 퀴즈), 퀴즈 추가·퀴즈 풀기 후·종료 시 `QuizGame.save()`가 쓴다.
- 파일이 없으면(첫 실행) 기본 퀴즈로 시작하고, 파일이 손상되어 JSON 파싱에 실패하면 안내 후 기본 퀴즈로 복구한다.

## 퀴즈 주제 선정 이유

주제는 '일본 애니메이션 제목 맞추기'로 **직접 선택**했다(지정 주제 아님). 주인공·줄거리·감독 같은 단서를 주고 제목 하나를 고르게 하면, 선택지 4개에 정답 하나로 깔끔하게 떨어지는 사실형 문제를 만들기 쉽고, 널리 알려진 작품이라 난이도도 적당하다. 기본 퀴즈는 소년만화(원피스·나루토), 다크 판타지(진격의 거인·귀멸의 칼날), 극장판(너의 이름은.), 심리물(데스노트) 등 서로 다른 결의 작품 6개를 골라 한쪽으로 쏠리지 않게 했다.

## 코드 구조와 설계

### 클래스 책임 분리

최소 2개 클래스 요건을 **역할**로 나눴다.

- **`Quiz`** — 개별 문제 하나를 책임진다. 데이터(`question`, `choices`, `answer`)와, 그 문제에 대한 동작(`show` 출력, `is_correct` 채점, `to_dict`/`from_dict` 변환)만 가진다. "이 문제가 자기 자신에 대해 할 수 있는 일"만 담는다.
- **`QuizGame`** — 게임 전체를 책임진다. 퀴즈 목록(`quizzes`)·최고 점수(`best_score`) 상태를 들고, 메뉴 흐름(`run`), 각 기능(`play`/`add_quiz`/`list_quizzes`/`show_score`), 파일 저장·불러오기(`save`/`load`)를 담당한다.

기준: **"하나의 문제"에 대한 것은 `Quiz`, "게임 전체"에 대한 것은 `QuizGame`.** 예를 들어 채점 규칙(`is_correct`)은 문제마다 다를 수 있으니 `Quiz`에 두고, 점수 집계·최고점 갱신은 게임 전체 상태라 `QuizGame`에 뒀다.

### 로직 분리 기준 (입력 / 게임 진행 / 저장)

- **입력 처리(검증)** — `read_int_in_range(prompt, low, high)` 함수 하나로 모았다. 메뉴 선택·정답 입력·추가 시 정답 번호가 모두 "정수 + 범위" 요건이라, 공백 제거·숫자 아님·범위 밖·빈 입력 처리를 한 곳에서 하고 재사용한다. 입력 검증을 각 기능에 흩뿌리지 않은 이유다.
- **게임 진행** — `QuizGame`의 각 메서드(`play`, `add_quiz`, …)가 담당. `run()`은 메뉴를 보여주고 번호에 맞는 메서드를 호출만 한다(분기와 실행을 분리).
- **데이터 저장/불러오기** — `save()`/`load()`로 격리. 다른 기능은 `self.quizzes`·`self.best_score`만 다루고, 파일 입출력은 이 두 메서드만 알면 되게 했다.

### 함수·메서드별 역할 (한 줄 정리)

- `read_int_in_range(prompt, low, high)` — 범위 안 정수가 들어올 때까지 반복 입력받는 공통 입력 검증 함수.
- `print_menu()` — 메뉴 화면 출력.
- `Quiz.__init__` — 문제·선택지·정답을 속성으로 저장.
- `Quiz.show()` — 문제와 1~4번 선택지를 출력.
- `Quiz.is_correct(user_input)` — 입력 번호가 정답과 같으면 `True`/아니면 `False` 반환.
- `Quiz.to_dict()` / `from_dict(data)` — 객체 ↔ 딕셔너리 변환(JSON 저장·복원용).
- `QuizGame.__init__` — 빈 퀴즈 목록과 최고 점수 0으로 시작.
- `QuizGame.load()` — `state.json`을 읽어 상태 복원. 없으면 기본 퀴즈, 손상되면 복구.
- `QuizGame.save()` — 현재 퀴즈·최고 점수를 `state.json`에 UTF-8로 저장.
- `QuizGame.play()` — 전체 문제 출제·채점, 점수 계산, 최고점 갱신.
- `QuizGame.add_quiz()` — 새 퀴즈 입력받아 등록·저장.
- `QuizGame.list_quizzes()` — 등록된 퀴즈 목록 출력.
- `QuizGame.show_score()` — 최고 점수 출력.
- `QuizGame.run()` — 메뉴 루프. 번호에 맞는 메서드 호출.

## 핵심 기술 원리

### 클래스를 쓴 이유 (함수만으로 짤 때와의 차이)

함수만으로 짜면 퀴즈 데이터(문제·선택지·정답)와 게임 상태(목록·최고점)가 전역 변수로 흩어지고, 모든 함수가 그 전역 데이터를 직접 건드린다. 클래스로 묶으면 데이터와 그 데이터를 다루는 동작이 한 덩어리가 되어, "누가 무엇을 책임지는지"가 분명해지고 퀴즈 하나를 객체로 다루기 쉬워진다(`quiz.is_correct(2)`처럼).

### JSON으로 저장하는 이유와 특징

파이썬의 `list`/`dict` 구조인 퀴즈 목록을 **구조 그대로** 텍스트로 저장·복원할 수 있고, 사람이 파일을 열어 읽기도 쉽다. JSON은 키-값(객체)과 배열로 이뤄진 범용 데이터 교환 형식이라 언어·도구 간 호환도 좋다. 한글이 `\uXXXX`로 깨지지 않게 `ensure_ascii=False`로 저장한다.

### try/except가 필요한 이유 (발생 가능한 실패 케이스)

파일 입출력은 프로그램 밖의 상태(파일 시스템)에 의존해서 실패할 수 있다. `load()`에서 대비하는 실패는 두 가지다.

- **파일이 없음**(첫 실행) → 기본 퀴즈로 시작.
- **파일 손상**(사람이 잘못 수정, 쓰다 중단 등) → `json.JSONDecodeError`/`KeyError` → 안내 후 기본 퀴즈로 복구.

이 처리가 없으면 손상된 파일 하나에 프로그램이 트레이스백을 내며 죽는다. 그래서 "읽기를 시도하고, 실패하면 안전한 기본값으로 되돌린다"는 흐름을 `try/except`로 감쌌다.

### 브랜치를 분리한 이유와 merge의 의미

'퀴즈 풀기' 기능을 `feature/play` 브랜치에서 작업한 뒤 `main`에 병합(`merge`)했다. 기능 단위로 `main`과 떨어져 독립적으로 만들고 검증한 다음 합치면, 작업 중인 미완성 코드가 `main`을 어지럽히지 않는다. `merge`는 그 브랜치의 작업 내용을 `main`의 역사에 합치는 것이고, `--no-ff`로 병합하면 "여기서 기능 브랜치가 합쳐졌다"는 흔적이 그래프에 남는다.

### state.json 구조를 현재 형태로 설계한 이유

최상위를 `{"quizzes": [...], "best_score": N}` 두 키로 단순하게 뒀다. 프로그램이 들고 있는 상태가 딱 이 둘(퀴즈 목록, 최고 점수)이라, 메모리 구조와 파일 구조를 1:1로 맞춰 읽고 쓰기를 단순하게 하려는 의도다. 각 퀴즈도 코드의 `Quiz` 속성과 같은 키(`question`/`choices`/`answer`)를 써서 `to_dict`/`from_dict`로 바로 오간다.

## 심층 설계 (확장·장애 대응)

- **퀴즈가 1000개 이상으로 늘면?** 지금은 저장·불러오기 때마다 **전체 JSON을 통째로** 읽고 쓴다. 개수가 커질수록 느려지고, 한 문제만 바꿔도 전체를 다시 쓴다. 메모리에도 전부 올린다. 그 규모에선 SQLite 같은 DB로 옮겨, 필요한 행만 읽고 쓰는 방식이 맞다.
- **state.json이 손상되면?** 현재는 파싱 실패를 감지해 **기본 퀴즈로 초기화**해 최소한 프로그램이 돌게 한다. 데이터 손실까지 막으려면 ① 저장 전에 기존 파일을 `state.json.bak`으로 백업, ② 저장을 임시 파일에 쓰고 성공 시 교체(원자적 쓰기)하는 방법이 있다(현재 미구현, 개선 여지로 명시).
- **채점 방식·선택지 개수 요구가 바뀌면 어디를 고치나?** 채점 규칙은 `Quiz.is_correct`, 점수 계산은 `QuizGame.play`, 선택지 개수는 입력받는 `add_quiz`의 `range(1, 5)`와 정답 범위 `read_int_in_range(..., 1, 4)`를 먼저 고친다. 데이터 구조(`choices` 길이)가 바뀌면 `state.json` 스키마와 `to_dict`/`from_dict`도 함께 본다. 책임을 나눠둔 덕에 바꿀 지점이 좁게 모인다.

## 부록 · 발표 자기점검 Q&A

발표에서 "설명할 수 있는가"로 물어볼 수 있는 항목을, 이 프로젝트 코드에 근거해 정리한다.

### 파이썬 기초

- **변수가 무엇이고 왜 쓰나?** 값에 이름을 붙여 저장·재사용하는 것. 이 코드에선 `self.best_score`에 최고 점수를, `correct`에 맞힌 개수를 담아 뒤에서 다시 꺼내 쓴다.
- **`int`/`str`/`bool`/`list`/`dict` 차이?** 이 코드 기준으로 — 정답 번호 `answer`는 `int`, 문제 `question`은 `str`, `is_correct`가 돌려주는 정답 여부는 `bool`, 선택지 `choices`는 `list`, `to_dict()` 결과는 `dict`.
- **`if/elif/else`?** `run()`에서 메뉴 번호(1~5)에 따라 다른 기능을 호출하는 분기에 쓴다.
- **`for` vs `while`?** 문제 개수가 정해진 출제 반복은 `for`(`play`의 `enumerate(self.quizzes, 1)`), 종료를 누를 때까지 도는 메뉴 반복은 `while True`(`run`). 횟수가 정해졌으면 `for`, 조건이 참인 동안이면 `while`.
- **함수의 매개변수·반환값?** `read_int_in_range(prompt, low, high)`는 세 매개변수를 받아 검증된 정수를 `return`으로 돌려준다.

### 클래스와 객체

- **클래스가 무엇이고 왜 쓰나?** 관련된 데이터와 동작을 묶은 설계도. `Quiz`로 문제 하나를, `QuizGame`으로 게임 전체를 객체로 다룬다(위 "클래스를 쓴 이유" 참고).
- **`__init__`과 `self`?** `__init__`은 객체를 만들 때 자동 호출되어 초기 속성을 세팅한다(`Quiz.__init__`에서 `self.question = question` 등). `self`는 메서드 안에서 그 객체 자신을 가리킨다.
- **속성과 메서드?** `quiz.question`은 속성(데이터), `quiz.is_correct(2)`는 메서드(동작).

### 파일 입출력

- **파일 열기/읽기/쓰기?** `with open(STATE_FILE, "r"/"w", encoding="utf-8") as f:`로 열고, 읽기는 `json.load(f)`, 쓰기는 `json.dump(data, f)`. `with`를 쓰면 블록이 끝날 때 파일이 자동으로 닫힌다.
- **JSON이 무엇이고 왜 저장에 쓰나?** 위 "JSON으로 저장하는 이유" 참고.
- **`try/except`?** 위 "try/except가 필요한 이유" 참고. 없는 파일·손상 파일 두 케이스를 잡는다.

### Git 기초

- **Git이 무엇이고 왜 필요한가?** 변경 이력을 기록해 되돌리고, 브랜치로 나눠 작업하고, 협업하기 위한 버전 관리 도구.
- **명령어별 역할**: `init`(저장소 생성) · `add`(변경을 스테이지에 올림) · `commit`(기록으로 확정) · `push`(원격에 올림) · `pull`(원격 변경 가져옴) · `checkout`(브랜치 이동/`-b`로 생성) · `clone`(원격을 통째로 복제) · `merge`(브랜치 합침).
- **브랜치 생성·병합?** `git checkout -b feature/play`로 만들어 작업하고, `git checkout main` 후 `git merge --no-ff feature/play`로 합쳤다.
- **clone·pull?** 저장소를 다른 폴더로 `clone`해 수정·`push`하고, 원본에서 `pull`로 가져와 반영을 확인했다.

- clone/pull 실습: 저장소를 별도 폴더로 복제해 동작을 확인함.
